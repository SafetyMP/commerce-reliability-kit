# Compatibility and versioning

Tool 0.1.0 remains an unpublished local candidate. Evidence/scenario/report schemas are now 1.1.0; rules are 1.1.1 and importer identity is normalized-1.1.0. Outcome, mapping, policy and scenario expectation versions remain 1.0.0. Capture interval sub-contract starts at version 1.0.0. The original six diagnostic outcomes and literal expectations remain unchanged; their evidence now explicitly declares point captures.

This is an explicit unpublished contract revision, not a published semver compatibility promise. Although captureInterval is additive and optional (omission means unknown), its prerequisite semantics and external capture assertion selection change results. Existing 1.0.0 envelopes/reports are rejected rather than silently reinterpreted. Migrate evidence intentionally as described in IMPORTS.md and regenerate reports under 1.1.0; preserve historical reports in their originating release. Comparison refuses incompatible versions. Tool/package version and protected dependency lock remain unchanged.

Rule 1.0.1's reviewed scope, chronology, reversal, persistence and location-qualified identity protections remain. Rule 1.1.0 adds explicit point-capture prerequisites and external diagnostic/finding assertions. External captures cannot rebind scenario source accounts or change policy. Fulfillment requires matching resource location sets. Inventory uses the latest source no later than target; intervening unpaired source reads reset persistence. Non-atomic/unknown capture intervals are not usable snapshot evidence. These conservative limits can delay findings. See [scenario authoring](SCENARIO-AUTHORING.md) for the current contract.

The locally exercised runtime is Node 22.23.2. Package engines declare >=22.23.0; other versions/platforms are not independently validated. Compiled ESM JavaScript and declarations are shipped; native TypeScript stripping is for source development only. Dependencies are pinned in the lockfile. No Shopify, ShipBob, onX, Pact, Airbyte, GX or CI-vendor compatibility is asserted.

Breaking field/status/quantity or timestamp semantics require a schema/rule major decision, migration notes, independent oracle review and new boundary probes. Additive compatible fields require a recorded version decision before release. Fixes affecting results must record the rule version and affected expectations; never silently rewrite historical reports. Unknown versions fail validation.

Report comparison requires identical tool/schema/rule/importer versions and workflow mode. Scenario identity/version, profile/policy/input hashes, evaluation time, coverage, mappings, assumptions and limitations are reported as context changes. Behavior is matched by stable check/assertion IDs or rule plus entity set, ignoring array order and evidence-ID-only changes. A behavior change under different context is not automatically a regression. Compare outputs informational changes and exits 0 for compatible reports, 3 for invalid/incompatible reports.

Completeness is always supplied, not independently established. Only filter=all scopes are supported; changing scope conservatively blocks continuity. Facility aggregation requires all declared disjoint members in shared complete snapshots with equivalent units/semantics. A milestone's timestamp proves only that declared milestone; delivered time alone does not establish when handoff occurred. Business calendars, fractional conversions and inferred bundle allocation are unsupported.

Rule 1.1.1 retains mapped order, orphan shipment and declared deadline subjects when prerequisite rows are missing or blocked. These subjects produce INCONCLUSIVE diagnostics rather than disappearing from finding-absence checks. Reports accept rule revisions 1.1.0 and 1.1.1 for reading, but comparison refuses different rule versions. See the regressions in `tests/contract-review.test.ts`.
